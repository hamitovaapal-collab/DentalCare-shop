# DentalCare Shop — комплексная повторная проверка

Дата: **10 ноября 2026 года**. Проверяется текущий проект `dentalcare-shop`; исходные данные и фотографии сохранены.

## Последний запрос: полный cobalt/ivory редизайн с сохранением фото и анимаций

Владелец подтвердил, что нужен **полностью другой интерфейс**, а не только День/Ночь. В новой рабочей версии оригинальная фотография hero находится слева, текст — справа на desktop. Используются отдельные карточки категорий, полноценный sidebar фильтров каталога с областью результатов и сортировкой, pill-CTA от 52px, компактные действия от 44px и круглые кнопки-иконки. Заголовки страниц и формы оформлены отдельными блоками. Дневной footer стал светлым с самостоятельным рядом бренда; Night согласован семантическими токенами. Для управления количеством обеспечивается видимый клавиатурный фокус.

Рабочая палитра — cobalt/ivory. Фотографии и их данные не заменяются, существующие анимации и reduced motion сохраняются. Прежние исправления форм, корзины, авторизации/RLS и API не откатываются. Публичная метка новой сборки `/build-info.json` — `cobalt-storefront`; вместе с ней доступны только проверенный Netlify COMMIT_REF и builtAt. При локальной сборке revision может быть null. Секреты не публикуются, для файла действует no-store.

При проверке 390×900 плавающий чат закрывал избранное второго товара. Кнопка чата перенесена в шапку, на мобильном экране рядом с меню, и больше не перекрывает карточки при прокрутке. Добавлен браузерный сценарий попадания в центр избранного, реального переключения, открытия чата и Escape на 320/390px в обеих темах. Клавиатурный контур количества больше не обрезается рамкой.

**Финальная cobalt-проверка: 127/127 браузерных, 7/7 production, свежая сборка и git diff --check — успешно.** Все 19 оригинальных JPG проверены SHA-256 и не изменились. Независимые 96 проверок шапки и 10 проверок каталога в обеих темах не выявили новых перекрытий или переполнения. Избранное под прежним чатом теперь доступно; меню/чат/Escape проверены повторно на 320/390px. Контраст подписей footer — 5,26:1 в Дне и 8,70:1 в Ночи. Реальный локальный код/сборка протестированы; контрактные сценарии не доказывают подключение к пользовательскому Supabase или доставку уведомлений. Live Netlify через эту среду не проверен.

## Что обнаружено и исправлено

1. **Потеря черновиков при обновлении сессии.** Supabase TOKEN_REFRESHED/повторный SIGNED_IN создавали новый объект user и повторно загружали профиль, размонтируя защищённые формы. Загрузка привязана к стабильному user ID. Профиль и вкладка админки сохраняют несохранённые данные.
2. **Устаревший initial session.** Поздний ответ getSession мог вернуть пользователя после более нового выхода. События auth теперь имеют приоритет, отписка и устаревшие ответы учитываются.
3. **Двойная отправка форм.** Добавлены синхронные блокировки для регистрации/восстановления/входа, отзывов и сохранения товара. Два submit в одном событии создают один запрос.
4. **Изменение черновика товара во время записи.** Edit/Back/поля/удаление блокируются во время сохранения/удаления. Успешное удаление редактируемого товара очищает его редактор, следующий Save не обновляет уже удалённый ID с ложным успехом.
5. **Неверная услуга при переходе по ссылкам.** Переходы между `/booking?service=...`, включая ту же ссылку после ручного выбора, синхронизируют услугу без потери имени, контактов и комментария. Старый ответ записи не подменяет новую форму.
6. **Данные подтверждения отличались от отправленных.** Пока запрос выполнялся, пользователь мог изменить поля, после чего WhatsApp показывал новые данные вместо заказа/записи. Подтверждение использует снимок отправленной формы.
7. **Новые количества пропадали из корзины.** При увеличении количества во время оформления ответ удалял весь товар из текущей корзины. Теперь вычитается только купленное количество; новые единицы и непокупавшиеся позиции остаются.
8. **Телефон из одной пунктуации.** Общая проверка для frontend и API требует 7–15 цифр, допускает обычное оформление и начальный плюс. Существующие номера +996 сохранены.
9. **Повреждённый request_id.** Массив с UUID проходил regex-приведение и приводил к ошибке RPC. API требует строку и возвращает 400 до записи.
10. **Дробные суммы в уведомлениях.** Числа вида `369.29999999999995` заменены корректным денежным форматированием. Цены/сумма в базе и ответе не подменяются.
11. **Чат «Контакты» по-русски.** Быстрый вопрос теперь находит контактный ответ и переход; раньше выдавался общий fallback.
12. **Чат на низком экране.** Поле и кнопка отправки обрезались на 320/390/768×375. Теперь панель помещается в окно, подсказки прокручиваются отдельно, сообщения остаются доступны. Escape закрывает чат с возвратом фокуса; при открытой основной модалке сначала закрывается только верхняя модалка.
13. **Зависимости.** `npm audit --omit=dev` нашёл две moderate-записи для React Router 6 (open redirect/SSR hydration). Обновлена та же библиотека до 7.18.5, совместимая с React 18 и Node 24. После обновления runtime-аудит сообщает **0 уязвимостей**. SSR в приложении не используется, внутренние redirect дополнительно проверяются самим приложением.

Новые цены, товары, фотографии, фиктивные учётные записи и публичный обход админских прав не создавались.

## Уровни доказательств

- Реальная локальная production-сборка и HTTP сервер: скомпилированные страницы, API, статические ресурсы и ошибки.
- Настоящий изолированный PostgreSQL 17: RLS, права, сохранение данных при повторном применении схемы, реальные конкурентные подключения, остатки/отмена/idempotency. Контейнер без сети; существующая база пользователя не затрагивается.
- Отдельный PGlite: транзакции и идемпотентность.
- Авторизованные браузерные сценарии и Telegram/Email используют изолированные контракты, включая отказы и задержки. Они не являются успешным подключением вашего Supabase или доставкой в ваш Telegram.

## Что в рабочей среде не подключено

Реальные Supabase/Telegram/Email настройки и Netlify account access отсутствуют. `check:services` возвращает код 2. Поэтому живые регистрация, вход владельца, назначение admin, запись заказа в вашу базу и получение настоящего уведомления **не подтверждены**. Email владельца, предоставленный в чате, сам по себе не создаёт аккаунт или права.

Внешний `https://dentalcare-shop.netlify.app/` блокируется Cloud-прокси до соединения (CONNECT 403). Это не 403 сайта. Shared Desktop/browser-control capability отсутствует. Сохранённый ранее draft разрешения домена ещё не применён к running environment. Версию публичного deploy через эту среду проверить нельзя; публикация исходников подтверждается отдельно через Git.

Для включения нужны реальные public URL/key и серверные настройки, схема и доверенное назначение роли. См. [ADMIN_ACCESS.md](ADMIN_ACCESS.md), [NETLIFY.md](NETLIFY.md), [TELEGRAM.md](TELEGRAM.md), [PRODUCTION.md](PRODUCTION.md). Пароли и секреты не пересылать в чат.

Также остаются исходные сведения, требующие подтверждения владельца: пример email `info@dentalcare.example`, адрес/данные клиники, действительность иллюстраций, цен и запасов. Карточные платежи в проекте не подключены и не имитируются.
