# Финальная комплексная проверка DentalCare-shop

Дата: 4 ноября 2026 года. Проверена текущая рабочая копия приложения `dentalcare-shop/`, а не опубликованная версия на внешнем домене.

## Что исправлено в финальной проверке

1. **Production-запуск.** Добавлен `npm start`: готовый `dist`, SPA-маршруты и настоящий Express API работают в одном процессе/origin. Dev- и production-серверы используют общую фабрику приложения. Express перенесён в runtime dependencies; выполнена чистая установка `npm ci --omit=dev` в отдельной копии с успешным запуском страниц и API.
2. **HTTP-ошибки.** Неверный JSON возвращает JSON `400 validation`, слишком большой запрос — `413`, неподдерживаемый метод — `405`, неизвестный API — JSON `404`. Отсутствующий asset не подменяется HTML-страницей с кодом 200. Добавлен безопасный `/api/health` с флагами конфигурации без значений секретов.
3. **Supabase configuration.** Неверный/шаблонный URL или пустой ключ больше не приводит к падению всего интерфейса при импорте SDK. Значения проверяются и очищаются от лишних пробелов. Авторизованный запрос при отсутствии backend-настроек получает `503 not_configured`, а не ложный отказ авторизации.
4. **Запись на приём.** Ошибка необязательного сохранения метаданных уведомления не превращает уже сохранённую запись в ответ «запись не выполнена», который мог провоцировать дубли.
5. **Повторная отправка.** Заказ и запись защищены от двух submit в одном событии/быстрых повторных отправок. Проверено, что отправляется ровно один запрос.
6. **Ожидание API.** Добавлен 30-секундный timeout с освобождением состояния отправки. Сообщение честно предупреждает: заявка могла сохраниться; перед повторной отправкой нужно проверить её/связаться с клиникой. Автоматического повторного создания заказа нет.
7. **Корзина и наличие.** Недоступные позиции не исчезают молча: видны, могут быть удалены, исключены из заказа/суммы. После покупки очищаются только действительно купленные позиции; недоступные сохраняются.
8. **Авторизация.** Переход после входа ограничен внутренними адресами, включая защиту от обратных слешей/управляющих символов. Сброс пароля без сессии восстановления предлагает новую ссылку вместо заведомо неуспешной отправки.
9. **Отзывы.** Автосмена слайда больше не отменяет ручной выбор. После взаимодействия автопрокрутка приостанавливается, есть отдельное возобновление. Автопрокрутка сохранена и проверена.
10. **Повторная SQL-установка.** Базовая схема применяется транзакционно; повторное создание её политик не прерывает установку и не перезаписывает существующий каталог/профили. Это проверено в реальном PostgreSQL.
11. **Сборка и чистка.** Удалён неиспользуемый импорт React, общие серверные обработчики не продублированы. React и Supabase выделены в отдельные кешируемые chunks; предупреждение о chunk >500 kB устранено разделением кода, а не повышением порога предупреждения.

## Настоящий PostgreSQL

`npm run test:postgres` создаёт отдельный PostgreSQL 17 в Docker **без сети и опубликованных портов**. Используется полный `schema.sql` и `checkout.sql`, а не упрощённая схема только таблиц заказов. После тестов удаляется только созданный этой командой контейнер.

Проверены:

- повторное применение схемы без потери каталога/профилей;
- создание профиля триггером регистрации;
- невозможность повышения собственной роли и чтения чужого профиля;
- скрытие неактивного товара и запрет редактирования каталога обычным пользователем;
- запрет прямого создания заказа/вызова service-only RPC из браузерной роли;
- принадлежность отзыва текущему пользователю;
- сумма по ценам базы, списание, отмена и повторная активация;
- два отдельных соединения, покупающие последние единицы: один заказ принят, другой отклонён, остаток неотрицателен;
- обратный порядок одинаковых товаров в двух соединениях: нет deadlock.

Это проверка настоящих PostgreSQL-транзакций и политик. Минимальная локальная `auth`-схема задаёт проверочные JWT subject для RLS; она не является работающим Supabase Auth и не заменяет ваш аккаунт.
